# BlogApp 진행 순서 (A팀)

> 순수 Java 콘솔 앱 / 메모리 저장 / 6인

---

## 1. 기능 의존 관계

기능은 나눠져 있지만 **혼자 완성할 수 있는 기능은 거의 없습니다.**
아래 화살표는 "A가 끝나야 B를 시작할 수 있다"는 뜻입니다.

```
사용자 등록(이한결)
   └─> 로그인(최미서) ──> 게시글 등록(류지훈)
                              ├─> 게시글 발행(이한결)
                              ├─> 게시글 목록(김경환)
                              ├─> 게시글 상세(엄예진)
                              ├─> 게시글 좋아요(최형선)
                              └─> 댓글 달기(최미서)
                                     ├─> 댓글 수정(류지훈)
                                     ├─> 댓글 삭제(김경환)
                                     └─> 댓글 좋아요(엄예진)

사용자 등록(이한결)
   └─> 이웃 신청(김경환) ──> 이웃 맺기(엄예진) ──> 이웃 해제(최미서)
                                                  └─> 이웃 관리(류지훈)

사용자 탈퇴(최형선)  ← 사용자 등록만 있으면 가능
```

**읽는 법**
- `게시글 목록`은 댓글 수·좋아요 수·조회 수를 함께 보여줘야 하므로, 세 기능이 없으면 **0으로 표시하고 나중에 연결**합니다. 서로 기다리지 마세요.
- `이웃` 계열 4개는 게시글/댓글과 완전히 독립입니다. 게시글 라인이 막혀도 이웃 라인은 계속 진행됩니다.

## 2. 단계별 순서

### 0단계 — 합의 (전원)

코드를 한 줄도 쓰기 전에 아래 5가지를 **말로 끝내고 결론을 적어둡니다.**

1. 도메인 클래스와 필드/타입 — `User`, `Post`, `Comment`, `Neighbor`
2. 데이터를 어디에 담을지 — 저장소 클래스 위치와 이름
3. 패키지·파일 구조
4. 브랜치 이름 규칙과 `main` 머지 방식
5. 콘솔 메뉴 번호 배정 (누가 몇 번 메뉴를 쓸지)

> 5번을 건너뛰면 6명이 전부 `Main`을 고쳐서 매번 충돌합니다. 미리 번호를 나눠 가지세요.

### 1단계 — 뼈대 커밋 (팀장)

합의한 내용을 **팀장 혼자** 코드로 만들어 `main`에 올립니다.

- 도메인 클래스 (필드 + 생성자 + getter/setter)
- 메모리 저장소 (`ArrayList` 보관용)
- 각 기능의 **빈 메서드**만 선언 (본문은 비워둠)
- `Main` 메뉴 뼈대

> 합의는 6명이 하되, **코드로 고정하는 손은 한 명**이어야 충돌이 안 납니다.
> 이 커밋이 올라간 뒤에 전원이 `git pull`로 받아가고 작업을 시작합니다.

### 2단계 — 기반 기능

| 담당 | 기능 | 비고 |
| --- | --- | --- |
| 이한결 | 사용자 등록 | **최우선.** 이게 없으면 아무도 로그인 못 함 |
| 최미서 | 로그인 | 등록 직후 착수. 비밀번호 10회 제한 포함 |
| 류지훈 | 게시글 등록 | 로그인 없이도 먼저 만들 수 있음 (테스트용 사용자로) |

나머지 3명(김경환·엄예진·최형선)은 이 단계에서 **이웃 라인**을 먼저 시작합니다.

- 김경환 → 이웃 신청
- 엄예진 → 이웃 맺기
- 최형선 → 사용자 탈퇴

### 3단계 — 조회 기능

게시글 등록이 `main`에 머지된 직후 착수합니다.

| 담당 | 기능 | 주의점 |
| --- | --- | --- |
| 김경환 | 게시글 목록 | 주인/비주인 구분해서 미발행 글 노출 여부 처리 |
| 엄예진 | 게시글 상세 조회 | 중복 조회 시 조회 수 증가 안 되게 (조회자 목록 필요) |
| 이한결 | 게시글 발행 | 목록에서 미발행 글 선택 → 발행 |

목록·상세에 들어가는 댓글 수, 좋아요 수는 **아직 0으로 두고 진행**합니다. 4단계 후 연결합니다.

### 4단계 — 댓글·좋아요

| 담당 | 기능 | 주의점 |
| --- | --- | --- |
| 최미서 | 댓글 달기 | **먼저.** 댓글이 있어야 수정·삭제·좋아요가 가능 |
| 최형선 | 게시글 좋아요 | 본인 글 금지 + 중복 금지 |
| 엄예진 | 댓글 좋아요 | 본인 댓글 금지 + 중복 금지 |
| 류지훈 | 댓글 수정 | 좋아요 1개 이상이면 수정 불가 |
| 김경환 | 댓글 삭제 | 좋아요 1개 이상이면 삭제 불가 |

> 댓글 수정·삭제는 **댓글 좋아요 기능에 의존**합니다(좋아요 수 확인). 엄예진과 먼저 좋아요 카운트를 어떻게 읽을지 맞추고 시작하세요.

### 5단계 — 이웃 마무리

| 담당 | 기능 |
| --- | --- |
| 최미서 | 이웃 해제 (양쪽에서 모두 제거) |
| 류지훈 | 이웃 관리 (목록 조회 등) |

### 6단계 — 통합 (전원)

1. 목록·상세 화면에 실제 댓글 수·좋아요 수·조회 수 연결
2. 전체 시나리오 테스트 — 등록 → 로그인 → 글 작성 → 발행 → 댓글 → 좋아요 → 이웃 → 탈퇴
3. 예외 케이스 점검 (아래 체크리스트)
4. 버그 수정 및 발표 준비

## 3. 통합 테스트 체크리스트

README에 명시된 제약 조건들입니다. 통합 단계에서 하나씩 확인하세요.

- [ ] 비밀번호 10회 이상 틀리면 로그인 차단
- [ ] 로그인 없이 게시글·댓글 작성 불가
- [ ] 블로그 주인만 미발행 글이 보임 / 다른 사용자는 발행 글만
- [ ] 같은 사용자가 재조회 시 조회 수 증가 안 함
- [ ] 본인 게시글에 좋아요 불가
- [ ] 본인 댓글에 좋아요 불가
- [ ] 같은 게시글·댓글에 중복 좋아요 불가
- [ ] 좋아요 1개 이상인 댓글은 수정·삭제 불가
- [ ] 이미 신청한 상대에게 재신청 불가
- [ ] 이웃 해제 시 양쪽 목록에서 모두 제거
- [ ] 이웃 거부 시 목록에 추가되지 않음
